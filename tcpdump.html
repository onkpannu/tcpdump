The tcpdump Field Guide

A comprehensive reference and conceptual framework for packet inspection, filtering, and deep protocol troubleshooting.

💡 The Core Philosophy

Don't think of tcpdump as a disconnected catalog of commands. Think of it as a expressive language for describing the exact packets you want to observe.

interface + protocol + host + network + port + direction + VLAN + packet size + flags + expressions

1. Starting with the Basics

#01 See Traffic on an Interface

Captures all traffic passing through the specified interface (e.g., eth0):

sudo tcpdump -i eth0
#02 Don't Resolve Names (-n & -nn)

Without -n, tcpdump attempts DNS resolution, converting IP addresses like 10.11.83.206 into hostnames. Always use numeric mode while learning and debugging.

sudo tcpdump -i eth0 -n

Distinction between -n and -nn:

  • -n: Do not resolve IP addresses to hostnames.
  • -nn: Do not resolve IP addresses and do not convert port numbers to named services.
sudo tcpdump -i eth0 -nn
#03 Show Ethernet MAC Addresses (-e)

Prints link-level header information revealing source MAC > destination MAC:

sudo tcpdump -i eth0 -n -e
#04 Verbosity Levels (-v, -vv, -vvv)

Controls the depth of header parsing (TTL, identification, protocol options):

sudo tcpdump -i eth0 -n -v # Standard verbose
sudo tcpdump -i eth0 -n -vv # More verbose (NFS, SMB decoding)
sudo tcpdump -i eth0 -n -vvv # Full header decode
#05 Hex + ASCII Payload Dumps (-X)

Inspects packet payloads in both hexadecimal and readable ASCII format:

sudo tcpdump -i eth0 -n -X
0x0040: 4865 6c6c 6f20 576f 726c 64 Hello World
#06 The Complete Frame Anatomy Command

The ultimate laboratory command for total visibility into the entire frame:

sudo tcpdump -i eth0 -nn -e -vvv -X

2. ICMP & ARP Diagnostics

#07 ICMP (Ping) Inspection

Observe ICMP echo requests and replies across the wire:

sudo tcpdump -i eth0 -nn -e icmp

Filter ICMP for a single host or specific operation types:

# Only ICMP to/from specific host sudo tcpdump -i eth0 -nn host 10.11.83.206 and icmp # Only ping requests (ICMP Type 8) sudo tcpdump -i eth0 -nn 'icmp[icmptype] == icmp-echo' # Only ping replies (ICMP Type 0) sudo tcpdump -i eth0 -nn 'icmp[icmptype] == icmp-echoreply'
Troubleshooting Pro-Tip: Filtering for requests vs replies immediately answers: "Is my host sending the ping, or is the remote gateway dropping the reply?"
#08 ARP (Address Resolution Protocol)

Watch IP-to-MAC resolution in real time:

sudo tcpdump -i eth0 -nn -e arp
Request who-has 10.11.80.196 tell 10.11.80.1
Reply 10.11.80.196 is-at 00:00:0a:0b:50:c4

Filter specific ARP opcodes (1 = Request, 2 = Reply):

# ARP Requests only sudo tcpdump -i eth0 -nn -e 'arp[6:2] == 1' # ARP Replies only sudo tcpdump -i eth0 -nn -e 'arp[6:2] == 2'

3. Host & Network Filtering

#09 Host Directives
# Bi-directional traffic for one host sudo tcpdump -i eth0 -nn host 10.11.83.206 # Only packets originating from host sudo tcpdump -i eth0 -nn src host 10.11.83.206 # Only packets destined to host sudo tcpdump -i eth0 -nn dst host 10.11.83.206
#10 Multi-Host Conversations

Isolate traffic strictly between two communicating endpoints:

sudo tcpdump -i eth0 -nn host 10.11.83.206 and host 10.11.80.196
#11 Subnet / Network Filtering (CIDR)

Crucial for troubleshooting routed network segments and subnets:

# Traffic involving the subnet sudo tcpdump -i eth0 -nn net 10.11.80.0/24 # Traffic from subnet sudo tcpdump -i eth0 -nn src net 10.11.80.0/24 # Traffic to subnet sudo tcpdump -i eth0 -nn dst net 10.11.80.0/24

4. Transport Layer (TCP, UDP & Applications)

#12 Port & Protocol Specifics
# General protocol filters sudo tcpdump -i eth0 -nn tcp sudo tcpdump -i eth0 -nn udp # Port filtering sudo tcpdump -i eth0 -nn tcp port 5000 sudo tcpdump -i eth0 -nn tcp src port 5000 sudo tcpdump -i eth0 -nn tcp dst port 5000 # Port ranges sudo tcpdump -i eth0 -nn 'tcp portrange 8000-9000' sudo tcpdump -i eth0 -nn 'udp portrange 5000-6000'
#13 Common Protocols (DNS, HTTP, DHCP, NetBIOS)
# DNS (Both TCP & UDP) sudo tcpdump -i eth0 -nn port 53 sudo tcpdump -i eth0 -nn udp port 53 sudo tcpdump -i eth0 -nn tcp port 53 # Web traffic & Unencrypted payloads sudo tcpdump -i eth0 -nn tcp port 80 sudo tcpdump -i eth0 -nn -X tcp port 80 sudo tcpdump -i eth0 -nn tcp port 443 # DHCP negotiation sudo tcpdump -i eth0 -nn 'udp port 67 or udp port 68' # NetBIOS Name Service & Broadcasts sudo tcpdump -i eth0 -nn udp port 137 sudo tcpdump -i eth0 -nn 'udp port 137 and dst host 255.255.255.255'
#14 Boolean Combinations & Exclusions
# Combine protocols sudo tcpdump -i eth0 -nn 'tcp or udp' sudo tcpdump -i eth0 -nn 'tcp or icmp' # Invert / Exclude protocols sudo tcpdump -i eth0 -nn 'not icmp' sudo tcpdump -i eth0 -nn 'not arp'

5. VLAN & Layer 2 Ethernet Frames

#15 VLAN Tagged 802.1Q Frames

When monitoring trunk links or tagged interfaces:

sudo tcpdump -i eth0 -nn -e vlan sudo tcpdump -i eth0 -nn -e 'vlan 100' sudo tcpdump -i eth0 -nn -e 'vlan 100 and ip' sudo tcpdump -i eth0 -nn -e 'vlan 100 and tcp port 443'

Frame encapsulation structure:

Destination & Source MAC
↓
802.1Q Header (VLAN Tag)
↓
IPv4 / IPv6 Header
↓
TCP / UDP Header
↓
Payload Data
#16 MAC Address & Multicast / Broadcast Filtering
# Match specific MACs (ideal for VM troubleshooting) sudo tcpdump -i eth0 -nn -e 'ether host 52:54:00:ba:51:21' sudo tcpdump -i eth0 -nn -e 'ether src 00:00:0a:0b:53:ce' sudo tcpdump -i eth0 -nn -e 'ether dst 00:00:0a:0b:50:c4' # Layer 2 & Layer 3 Broadcast sudo tcpdump -i eth0 -nn -e ether broadcast sudo tcpdump -i eth0 -nn 'dst host 255.255.255.255' # Layer 2 & Layer 3 Multicast sudo tcpdump -i eth0 -nn -e ether multicast sudo tcpdump -i eth0 -nn ip multicast

6. TCP Flags & Stateful Handshakes

#17 Bitmask Flag Filtering

Inspect exact control flags using TCP offset expressions:

# SYN - Connection initiation sudo tcpdump -i eth0 -nn 'tcp[tcpflags] & tcp-syn != 0' # ACK - Acknowledgements sudo tcpdump -i eth0 -nn 'tcp[tcpflags] & tcp-ack != 0' # FIN - Clean teardown sudo tcpdump -i eth0 -nn 'tcp[tcpflags] & tcp-fin != 0' # RST - Connection reset / rejected sudo tcpdump -i eth0 -nn 'tcp[tcpflags] & tcp-rst != 0' # PSH - Push data sudo tcpdump -i eth0 -nn 'tcp[tcpflags] & tcp-push != 0'
#18 Tracking the Three-Way Handshake

Watch state transitions live without hex payload clutter:

sudo tcpdump -i eth0 -nn -e tcp port 5000
Client → Server Flags [S] (SYN) Server → Client Flags [S.] (SYN-ACK) Client → Server Flags [.] (ACK)
#19 Packet Size & MTU Diagnostics
# Small packets (e.g., pure ACKs, keepalives) sudo tcpdump -i eth0 -nn 'less 100' # Large packets (e.g., MTU / jumbo frame testing) sudo tcpdump -i eth0 -nn 'greater 1400' # Packets within a specific size bracket sudo tcpdump -i eth0 -nn 'greater 100 and less 500'

7. Capture Operations & Analysis Workflows

#20 Capture to PCAP & Offline Analysis
# Capture full packet (-s 0) to file sudo tcpdump -i eth0 -nn -s 0 -w capture.pcap # Read and inspect stored capture offline tcpdump -nn -r capture.pcap tcpdump -nn -e -vvv -r capture.pcap tcpdump -nn -e -vvv -X -r capture.pcap
#21 Interfaces, Limits & Timestamps
# Limit packet count and exit sudo tcpdump -i eth0 -nn -c 20 # Formatted human-readable timestamps (YYYY-MM-DD HH:MM:SS) sudo tcpdump -i eth0 -nn -tttt # Print numbered packet index sudo tcpdump -i eth0 -nn -# # Loopback & pseudo-device captures sudo tcpdump -i lo -nn sudo tcpdump -i any -nn

8. Filter Operators Reference

Operator / Keyword Category Description / Purpose
andLogicalBoth conditions must evaluate to true
orLogicalEither condition may evaluate to true
notLogicalNegates / excludes condition
hostAddressingMatches IPv4 / IPv6 source or destination
src / dstDirectionSpecifies packet origin or target
netAddressingMatches subnet in CIDR format
port / portrangeTransportMatches Layer 4 port or numeric span
tcp / udp / icmp / arpProtocolFilters specific protocol header
vlanLayer 2802.1Q tagged frame header
etherLayer 2Matches Ethernet MAC, broadcast, or multicast
Precedence Warning: When combining and and or operators, always isolate them using quotes and parentheses to prevent unintended filter precedence:
sudo tcpdump -i eth0 -nn '(tcp port 80 or tcp port 443) and host 10.11.83.206'
Previewing IPv6: In IPv6 environments, ARP is replaced with ICMPv6 Neighbor Discovery (Router & Neighbor Solicitations/Advertisements). Filter with:
sudo tcpdump -i eth0 -nn -e icmp6
